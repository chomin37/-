# ABLE GYM START 28 — 무료 웹앱

에이블짐 수명산파크점 회원용 4주 운동습관 형성 웹앱. 주 2/3/4회 공통 프로그램(8/12/16회), 관리자 종목·세트·횟수·권장요일 수정, 회원별 출석·운동완료 체크, 진행률, 회원별 프로그램 배정 지원.

## 중요: 실행 준비

이 파일은 **실제 동작하는 웹앱 소스**지만, 회원 데이터가 저장되는 기능을 사용하려면 무료 Supabase 프로젝트 연결이 **필수**입니다. 파일만 열거나 압축을 풀기만 해서는 로그인할 수 없습니다. 관리자 계정은 최초 1회 수동 승격해야 합니다. 서비스 이용량이 무료 요금제 범위를 넘으면 요금 또는 제한이 발생할 수 있습니다.

### 1. Supabase 만들기
1. https://supabase.com/ 에 가입하여 새 프로젝트를 만듭니다.
2. SQL Editor에서 `schema.sql` 파일 전체를 실행합니다.
3. Authentication → Providers → Email에서 **Confirm email을 OFF**로 설정합니다. (실제 메일 주소가 아닌 회원번호 로그인 방식)
4. Project Settings / API Keys 화면에서 **Project URL** 및 **publishable key** 또는 legacy **anon key**를 확인합니다.
5. `config.js`의 `YOUR_SUPABASE_URL`, `YOUR_SUPABASE_ANON_KEY`를 실제 값으로 바꿉니다. **service_role/secret 키는 절대 넣지 마세요.**

### 2. 최초 관리자 계정 만들기
1. Supabase → Authentication → Users → Add user에서 관리자 계정을 만듭니다.
2. 이메일은 `manager01@members.ablegym.invalid`, 비밀번호는 임의의 강력한 비밀번호로 지정합니다. 이메일 확인은 하지 않도록 생성합니다.
3. SQL Editor에서 아래 SQL을 실행합니다.
   ```sql
   update public.profiles set role='admin', display_name='관리자' where member_no='manager01';
   ```
4. 웹앱 로그인 화면에서 회원번호 `manager01`과 해당 비밀번호로 로그인합니다.
5. 관리자 탭에서 회원번호, 이름, 초기 비밀번호, 주간 운동 횟수를 입력해 회원을 생성합니다.

**참고:** 최초 관리자 생성 시 프로필이 없다면 SQL trigger 설치 여부와 사용자 이메일을 확인하세요. `profiles`에 회원번호가 저장되며 대소문자 혼용을 피하고 소문자 회원번호 사용을 권장합니다.

### 3. 무료 배포: GitHub Pages
1. https://github.com/ 에 가입하여 새 **Public** 저장소를 만듭니다.
2. `index.html`, `app.js`, `config.js`, `manifest.webmanifest`를 저장소 루트에 업로드합니다. (`schema.sql`과 README는 업로드 선택 사항)
3. Settings → Pages → Build and deployment → Deploy from a branch → main / root 선택 → Save.
4. 배포된 주소(예: `https://아이디.github.io/저장소명/`)를 회원들에게 공유합니다.
5. 회원은 휴대폰 브라우저에서 열어 홈 화면에 추가하면 앱처럼 이용할 수 있습니다.

## 운영 및 권한
- **관리자**: 공통 운동 프로그램 수정, 회원 생성, 회원 프로그램 배정, 출석/운동완료 현황 조회.
- **회원**: 본인에게 배정된 운동 확인, 출석 체크, 운동완료 체크, 개인 달성률 확인.
- DB Row Level Security(RLS)가 관리자/회원 권한을 **서버에서 강제**합니다. 단순히 버튼을 숨기는 방식이 아닙니다.
- 회원 등록은 관리 화면에서만 제공하지만 Supabase Auth의 일반 signUp API가 활성화되어 있으므로, 외부에서 임의 계정 생성 자체를 원천 차단하려면 추후 서버 측 관리자 전용 회원생성 Edge Function을 구현하고 공개 가입을 비활성화해야 합니다. 현재도 임의 가입자는 **관리자 권한을 획득할 수 없습니다**.
- 회원번호는 3~32자의 영문/숫자/`_`/`-`를 사용하세요. 대소문자는 내부적으로 소문자로 처리됩니다.
- 초기 비밀번호는 최소 8자이며, 실제 운영에서는 길고 고유한 비밀번호를 권장합니다.
- 로그는 4주 1사이클 기준으로 저장됩니다. 재참여 시 로그 초기화/사이클별 이력 기능은 아직 포함되지 않았습니다.
- 회원 비밀번호 변경·재설정 기능, 출석 위치 검증, 대량 회원 업로드, SMS 알림, 회원 삭제, 운동일 자동 달력 연동은 미구현입니다.
- 관리자 프로그램 변경은 모든 해당 유형 회원에게 적용됩니다. 주차별 일차 수(2/3/4)는 고정이고, **권장 요일**은 수정할 수 있습니다.

## 테스트 체크리스트
- 관리자 로그인 → 관리자 탭 표시
- 주2/3/4회 각 4주 선택 → 운동 수정 → 저장 후 새로고침해도 유지
- 회원 생성 → 회원 계정으로 로그인 → 관리자 탭 미표시
- 출석 및 운동완료 체크 → 새로고침 후 유지
- 관리자 회원 목록에서 완료 횟수 확인 및 주간 운동 횟수 변경
- 다른 회원으로 로그인해 타인 기록 조회/수정 불가(RLS)

## 개인정보 안내
회원번호와 이름, 출석·운동 이력을 저장합니다. 운영 전에 개인정보 수집·이용 안내 및 접근 권한, 데이터 보관·삭제 정책을 준비하세요. 실제 회원번호 대신 내부 임의 식별번호를 쓰는 편이 안전합니다. 앱 파일을 공개 저장소에 올릴 때 **비밀번호나 관리자 secret/service_role 키를 넣지 마세요.**
